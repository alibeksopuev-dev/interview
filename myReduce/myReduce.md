# Реализация `Array.prototype.myReduce`

## Условие задачи

Реализовать метод `myReduce` на прототипе `Array`, который ведёт себя идентично нативному `Array.prototype.reduce`:
- Применяет колбэк-функцию к каждому элементу массива (слева направо), накапливая единое результирующее значение.
- Поддерживает необязательный аргумент `initialValue` в качестве начального значения аккумулятора.
- Если `initialValue` не предоставлен:
  - Первый существующий элемент массива становится начальным значением аккумулятора.
  - Итерация начинается со следующего существующего элемента.
  - Если массив пустой (или состоит только из пустых ячеек/дыр) и `initialValue` не передан, выбрасывает `TypeError`.
- **Сохраняет разреженность**: пустые ячейки (holes) в разреженных массивах игнорируются и не передаются в колбэк.

---

## Реализация

```typescript
export {}

declare global {
  interface Array<T> {
    myReduce(
      callbackFn: (previousValue: T, currentValue: T, currentIndex: number, array: T[]) => T,
    ): T
    myReduce<U>(
      callbackFn: (previousValue: U, currentValue: T, currentIndex: number, array: T[]) => U,
      initialValue: U,
    ): U
    myReduce<U>(
      callbackFn: (previousValue: U | T, currentValue: T, currentIndex: number, array: T[]) => U,
    ): U | T
  }
}

Array.prototype.myReduce = function <T, U>(
  this: T[],
  callbackFn: (
    previousValue: any,
    currentValue: T,
    currentIndex: number,
    array: T[],
  ) => any,
  initialValue?: U,
): any {
  // Проверяем количество аргументов, чтобы отличить явную передачу `undefined` в качестве initialValue
  // от ситуации, когда аргумент вообще не был передан.
  const noInitialValue = arguments.length <= 1
  const arrayLength = this.length

  let index = 0
  let accumulator: any

  if (noInitialValue) {
    // Ищем первый существующий индекс (пропускаем дыры в начале разреженного массива)
    while (index < arrayLength && !Object.hasOwn(this, index)) {
      index++
    }

    // Если массив пустой (или содержит только дыры) и начальное значение не задано — выбрасываем ошибку
    if (index >= arrayLength) {
      throw new TypeError('Reduce of empty array with no initial value')
    }

    accumulator = this[index]
    index++
  } else {
    accumulator = initialValue
  }

  for (; index < arrayLength; index++) {
    // Пропускаем несуществующие индексы (holes)
    if (Object.hasOwn(this, index)) {
      accumulator = callbackFn(accumulator, this[index], index, this)
    }
  }

  return accumulator
}
```

## Ключевые детали

### 1. `arguments.length <= 1` vs `initialValue === undefined`

Для определения наличия начального значения используется проверка количества переданных аргументов через `arguments.length`. Сравнение `initialValue === undefined` здесь **не подходит**, поскольку:
* `undefined` может быть передан пользователем как **явный** первый аргумент (`initialValue`).
* Нативный `Array.prototype.reduce` отличает ситуацию «передали `undefined`» от «не передали ничего». Проверка количества аргументов позволяет нам в точности повторить это поведение.

```typescript
// initialValue передан явно как undefined
[1, 2].myReduce((acc, val) => acc + '-' + val, undefined); // 'undefined-1-2'

// initialValue опущен
[1, 2].myReduce((acc, val) => acc + '-' + val);            // '1-2'
```

### 2. Skip-and-seed (пропуск дыр при инициализации)

Если начальное значение не передано, аккумулятор должен инициализироваться первым **существующим** элементом массива. Для разреженных массивов (например, `[, , 1, 2, 3]`) мы не можем просто взять `this[0]`, так как индекса `0` не существует.

Для этого в коде используется предварительный цикл:
```typescript
while (index < arrayLength && !Object.hasOwn(this, index)) {
  index++
}
```
Он сдвигает указатель `index` на первый существующий индекс, значение по которому становится начальным аккумулятором `accumulator`, после чего итерация продолжается со следующего индекса (`index++`).

### 3. Использование `Object.hasOwn(this, index)`

Для проверки существования элемента используется метод `Object.hasOwn()`. Он проверяет только **собственные** свойства объекта, исключая свойства из прототипов. Это защищает от ложного срабатывания, если на прототип `Array.prototype` было записано какое-то свойство с числовым ключом.

## Пошаговое выполнение

### Пример 1. С начальным значением

Запуск: `[1, 2, 3].myReduce((acc, value) => acc + value, 4)`

| Индекс `index` | Текущий элемент `value` | `acc` перед колбэком | Результат колбэка |
|:--------------:|:-----------------------:|:--------------------:|:-----------------:|
| **0** | `1` | `4` | `5` |
| **1** | `2` | `5` | `7` |
| **2** | `3` | `7` | `10` |

*Результат:* `10`

### Пример 2. Без начального значения

Запуск: `[1, 2, 3].myReduce((acc, value) => acc + value)`

| Индекс `index` | Текущий элемент `value` | `acc` перед колбэком | Результат колбэка |
|:--------------:|:-----------------------:|:--------------------:|:-----------------:|
| **0** | *(пропускается)* | `acc` инициализируется значением `1` (первый элемент) | *(вызов колбэка пропущен)* |
| **1** | `2` | `1` | `3` |
| **2** | `3` | `3` | `6` |

*Результат:* `6`

## Граничные случаи

1. **Пустой массив без `initialValue`**:
   - `[].myReduce((acc, x) => acc + x)` — выбрасывает `TypeError`.
2. **Пустой массив с `initialValue`**:
   - `[].myReduce((acc, x) => acc + x, 10)` — возвращает `10` (колбэк не вызывается).
3. **Массив из одного элемента без `initialValue`**:
   - `[5].myReduce((acc, x) => acc + x)` — возвращает `5` (колбэк не вызывается).
4. **Массив из одного элемента с `initialValue`**:
   - `[5].myReduce((acc, x) => acc + x, 10)` — возвращает `15` (колбэк вызывается один раз).
5. **Разреженный массив с «дырами» внутри**:
   - `[1, , 3, 4]` — пустые слоты игнорируются, колбэк вызывается только для индексов `0`, `2`, `3`.
6. **Разреженный массив без `initialValue` и с дырами в начале**:
   - `[, , 2, , 4].myReduce((acc, x) => acc + x)` — `acc` инициализируется числом `2` (индекс `2`), итерация продолжается для элемента `4` (индекс `4`). Возвращает `6`.
7. **Разреженный массив из одних дыр без `initialValue`**:
   - `[, , ,]` — ведет себя как пустой массив и выбрасывает `TypeError`.

## Частые ошибки (Common Pitfalls)

1. **Игнорирование параметров колбэка**:
   Не забывайте передавать в колбэк `currentIndex` и ссылку на сам массив `array`:
   ```typescript
   accumulator = callbackFn(accumulator, this[index], index, this)
   ```
2. **Некорректное выявление отсутствия `initialValue`**:
   Использование конструкции `initialValue === undefined` вместо `arguments.length <= 1` приводит к багам при явной передаче `undefined` в качестве начального значения.

## Важные примечания (Мутация массива по спецификации TC39)

Если массив изменяется в процессе выполнения `myReduce`, поведение должно следовать спецификации:
* Диапазон элементов, которые будут обработаны, фиксируется **до** первого вызова колбэка (сохранением длины в `arrayLength`).
* Элементы, добавленные в массив после начала выполнения `myReduce`, **не будут** обработаны колбэком.
* Если существующие элементы массива меняются в процессе работы, колбэку будет передано их значение на момент посещения этого индекса.
* Если элемент массива был удален до того, как итерация дошла до него, этот индекс будет пропущен (так как `Object.hasOwn` вернет `false`).

## Особенности типизации в TypeScript

При использовании строгого режима компилятора (`strict: true`) вы можете столкнуться со следующими особенностями типизации при тестировании `myReduce`:

### 1. Зачем нужны три перегрузки `myReduce`?

В TypeScript-объявлении метода `myReduce` описаны три сигнатуры:
```typescript
interface Array<T> {
  // 1. Возвращаемый тип совпадает с типом элементов массива, начальное значение опущено
  myReduce(
    callbackFn: (previousValue: T, currentValue: T, currentIndex: number, array: T[]) => T,
  ): T
  
  // 2. Начальное значение передано (тип U), метод возвращает этот же тип U
  myReduce<U>(
    callbackFn: (previousValue: U, currentValue: T, currentIndex: number, array: T[]) => U,
    initialValue: U,
  ): U
  
  // 3. Начальное значение опущено, но тип аккумулятора меняется с T на U в процессе выполнения
  myReduce<U>(
    callbackFn: (previousValue: U | T, currentValue: T, currentIndex: number, array: T[]) => U,
  ): U | T
}
```

Каждая перегрузка отвечает за свой сценарий использования:
* **Первая сигнатура** обрабатывает самый простой случай: агрегирование без указания `initialValue` (например, `[1, 2, 3].myReduce((acc, x) => acc + x)`). Тип аккумулятора и результата совпадает с типом элементов массива (`T`).
* **Вторая сигнатура** используется, когда задано начальное значение `initialValue` (тип `U`). Поскольку аккумулятор начинает со значения типа `U`, он всегда имеет тип `U` (даже если он отличается от `T`, например, преобразование массива чисел в строку-аккумулятор: `[1, 2].myReduce((acc, x) => acc + x, '')`). В этой сигнатуре `initialValue` является обязательным параметром.
* **Третья сигнатура** нужна для редких сценариев, когда начальное значение не передано, но тип аккумулятора меняется в процессе свертки (например, `[1, 2].myReduce<any>((acc, x) => acc + '-' + x)`). На первом шаге `previousValue` инициализируется первым элементом массива (тип `T`), но колбэк возвращает строку (тип `U`). На последующих шагах `previousValue` уже равен `U`. Поэтому типом аккумулятора выступает объединение `U | T`, а возвращаемое значение метода может быть `U | T`.

Если бы мы попытались объединить всё в одну сигнатуру вроде `myReduce<U>(callbackFn: ..., initialValue?: U): U`, то:
* При вызове без `initialValue` компилятор не знал бы, что в качестве стартового аккумулятора используется элемент массива типа `T`. Тип `U` в таком случае вывелся бы как `unknown` или `undefined`, и код внутри колбэка не прошел бы строгие проверки типов.
* Нам пришлось бы сделать параметр `initialValue` необязательным (`initialValue?: U`) во всех случаях, что ослабило бы строгость проверок для сценариев с типом `U`, отличным от `T`.

Именно по этим причинам в стандартной библиотеке TypeScript (`lib.es5.d.ts`) нативный `Array.prototype.reduce` типизирован с использованием нескольких перегрузок.

### 2. Типизация разреженных и пустых массивов в тестах

* **Разреженные массивы**: При объявлении массивов с пропусками вроде `[1, , 3]` TypeScript выводит тип как `(number | undefined)[]`. Из-за этого внутри колбэка `val` будет иметь тип `number | undefined`, что приведёт к ошибке `Possibly 'undefined'`. Для исправления этого в тестах используется явное приведение типов: `([1, , 3] as number[])`.
* **Пустые массивы**: Массив `[]` типизируется как `never[]`. Попытка запустить `reduce` на нём вызовет ошибку `Type 'number' is not assignable to type 'never'`. Для тестов используйте явное приведение: `([] as number[])`.

## Сложность алгоритма

- **Временная сложность**: $O(n)$ — один проход по массиву.
- **Пространственная сложность**: $O(1)$ — в отличие от `myMap`/`myFilter`, метод `reduce` возвращает единственное значение и не создает новые массивы для хранения результатов промежуточных шагов.

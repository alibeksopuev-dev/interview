# Реализация `Array.prototype.myFilter`

## Условие задачи

Реализовать метод `myFilter` на прототипе `Array`, который ведёт себя идентично нативному `Array.prototype.filter`:
- Проходит по всем элементам исходного массива, пропуская пустые ячейки (holes) в разреженных массивах.
- Вызывает функцию-колбэк (предикат) для каждого существующего элемента, передавая туда текущее значение, индекс и сам исходный массив.
- Поддерживает необязательный аргумент `thisArg` для привязки контекста `this` внутри колбэка.
- Возвращает **новый плотный** массив, содержащий только те элементы исходного массива, для которых колбэк вернул истинное (truthy) значение.
- Не изменяет исходный массив.

---

## Реализация

```typescript
export {};

declare global {
  interface Array<T> {
    myFilter(
      callbackFn: (value: T, index: number, array: Array<T>) => boolean,
      thisArg?: any,
    ): Array<T>;
  }
}

Array.prototype.myFilter = function <T>(
  this: T[],
  callbackFn: (value: T, index: number, array: T[]) => boolean,
  thisArg?: any,
): T[] {
  const arrayLength = this.length;
  const array: T[] = [];

  for (let index = 0; index < arrayLength; index++) {
    if (
      Object.hasOwn(this, index) &&
      callbackFn.call(thisArg, this[index], index, this)
    ) {
      array.push(this[index]);
    }
  }

  return array;
};
```

## Ключевые детали

### 1. `[]` и `array.push` для построения результата

В отличие от `myMap`, где результирующий массив должен сохранять исходную длину и пустые ячейки (holes), `myFilter` возвращает плотный массив, содержащий только отфильтрованные элементы.
Поэтому мы инициализируем обычный пустой массив `const array = []` и наполняем его с помощью стандартного метода `array.push(...)`:
```typescript
array.push(this[index]);
```
Это гарантирует, что в результирующем массиве не будет никаких дыр, а его длина будет точно равна числу элементов, для которых предикат вернул истинное значение.

### 2. Проверка `Object.hasOwn(this, index)` — пропуск дыр

Нативный метод `filter` посещает только те индексы массива, у которых есть присвоенные значения (включая `undefined`, если оно было присвоено явно). Пустые ячейки (пропуски/holes) игнорируются:

```typescript
const sparse = [1, , 3];
// Индекс 1 пропущен, колбэк для него вызываться не будет
sparse.myFilter(x => x !== undefined); // [1, 3]
```

Использование `Object.hasOwn(this, index)` гарантирует, что мы не будем вызывать колбэк для несуществующих индексов разреженного массива.

### 3. Значение предиката приводится к true/false неявно или явно в условии `if`

В нашей реализации условие проверки выглядит так:
```typescript
if (
  Object.hasOwn(this, index) &&
  callbackFn.call(thisArg, this[index], index, this)
)
```
Поскольку результат `callbackFn.call` используется непосредственно в условии `if`, JavaScript автоматически приводит возвращаемое значение колбэка к логическому типу (Boolean). Это полностью соответствует поведению встроенного `filter`.

---

### 4. В чем разница между `this` и `thisArg`?

*   **`this` (контекст вызова метода `myFilter`)**
    *   Указывает на массив, на котором был вызван метод.
    *   В типизации `this: T[]` — это псевдопараметр TypeScript, сообщающий компилятору тип контекста.
*   **`thisArg` (контекст для вызова колбэка)**
    *   Необязательный второй параметр метода `myFilter`.
    *   Задает значение `this` при вызове функции `callbackFn`.
    *   Позволяет использовать внешние объекты внутри обычных функций-колбэков (для стрелочных функций контекст не меняется из-за лексического связывания).

Пример:
```typescript
const filterer = {
  minLimit: 10,
  isAboveLimit(value: number) {
    return value > this.minLimit; // this ссылается на filterer благодаря передаче thisArg
  }
};

const numbers = [5, 12, 8, 20];
const result = numbers.myFilter(filterer.isAboveLimit, filterer); // [12, 20]
```

---

### 5. Три параметра `callbackFn` и их назначение

Предикат вызывается со следующими параметрами: `callbackFn(value, index, array)`

1.  **`value`** — текущий элемент массива (`this[index]`).
2.  **`index`** — числовой индекс текущего элемента (`index`).
3.  **`array`** — ссылка на оригинальный массив, по которому осуществляется проход (`this`).

---

### 6. Зачем нужен `callbackFn.call`

Для вызова колбэка с передачей кастомного контекста `thisArg` используется метод `.call()`:
```typescript
callbackFn.call(thisArg, this[index], index, this);
```
Метод `.call` первым параметром принимает объект, который станет контекстом `this` внутри вызываемой функции, а последующие параметры передаются как аргументы функции.

---

### 7. Подробный разбор типизации

```typescript
export {}; // Делает файл модулем для изоляции типов

declare global {
  interface Array<T> {
    myFilter(
      callbackFn: (value: T, index: number, array: Array<T>) => boolean,
      thisArg?: any,
    ): Array<T>;
  }
}
```

*   **`interface Array<T>`** — расширяет стандартный глобальный интерфейс массива с помощью Declaration Merging.
*   **`callbackFn: (value: T, index: number, array: Array<T>) => boolean`** — типизация колбэка-предиката. Возвращаемое значение типизировано как `boolean`.
*   **`thisArg?: any`** — опциональный аргумент для проброса контекста.
*   **`Array<T>`** — возвращаемый тип. Метод `filter` возвращает массив того же типа, что и исходный (или его подмножество типов).

## Пошаговое выполнение `[1, 2, , 4].myFilter(x => x % 2 === 0)`

| Шаг | `index` | Есть элемент? (`Object.hasOwn`) | Результат предиката | Действие | Состояние `array` |
|:---:|:-------:|:------------------------------:|:-------------------:|:--------:|:-----------------:|
| 1 | 0 | `true` (значение: `1`) | `false` | Пропущен | `[]` |
| 2 | 1 | `true` (значение: `2`) | `true` | Добавлен | `[2]` |
| 3 | 2 | `false` (дыра) | Не вызывается | Пропущен | `[2]` |
| 4 | 3 | `true` (значение: `4`) | `true` | Добавлен | `[2, 4]` |

Результат: `[2, 4]`

## Частые вопросы

### Зачем длина массива сохраняется в `arrayLength` до цикла?

По спецификации длина массива фиксируется перед первым вызовом колбэка. Если колбэк в процессе работы начнет добавлять новые элементы в исходный массив, они не будут посещены, так как цикл остановится на исходном значении `arrayLength`.

### Почему используется `Object.hasOwn` вместо `index in this`?

Оператор `in` проверяет наличие свойства не только у самого объекта, но и во всей его цепочке прототипов. Если кто-то добавит свойство с числовым ключом в `Array.prototype` (например, `Array.prototype[1] = 'test'`), то `in` вернет `true` для пустой ячейки разреженного массива под индексом `1`. `Object.hasOwn` проверяет исключительно собственные свойства объекта, гарантируя корректное поведение.

## Сложность алгоритма

- **Временная сложность**: $O(n)$ — один проход по массиву длины $n$.
- **Пространственная сложность**: $O(n)$ — в худшем случае (когда все элементы подходят под условие) создается новый массив той же длины.

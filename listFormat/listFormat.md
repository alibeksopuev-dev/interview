# Разбор алгоритма `listFormat` (Big O + пошаговый разбор)

> Как форматировать массивы строк в понятный человеку текстовый список с поддержкой сортировки, дедупликации и лимита длины.

---

## 📌 Введение: в чём идея?

Функция `listFormat` принимает массив строк и объединяет его элементы в одну строку, разделяя их запятыми, а последний элемент присоединяет через союз `" and "` (например: `['яблоко', 'банан', 'груша']` превращается в `"яблоко, банан and груша"`).

Помимо базового объединения, функция поддерживает объект конфигурации `options` со следующими возможностями:
1. **`sorted?: boolean`** — если `true`, элементы сортируются по алфавиту перед форматированием.
2. **`unique?: boolean`** — если `true`, удаляет повторяющиеся значения (дубликаты) из списка.
3. **`length?: number`** — ограничивает количество выводимых элементов. Оставшаяся часть скрывается за подписью вида `X other` (если остался 1 элемент) или `X others` (если осталось больше одного).

Также функция производит предварительную очистку данных: отбрасывает пустые или falsy-строки (например, `""`).

---

## ⏱️ 1. Временная сложность (Time Complexity)

Временная сложность алгоритма зависит от переданных флагов конфигурации. Обозначим `N` как количество элементов во входном массиве `itemsParam`, а `L` — суммарную длину всех строк.

### Худший сценарий (при включении всех опций): `O(N log N + L)`

1. **Фильтрация (`filter`):** `O(N)` — мы обходим весь массив один раз, чтобы отсеять пустые элементы.
2. **Сортировка (`sort`):** `O(N log N * K)` — в среднем и худшем случае встроенная сортировка движка V8 требует `O(N log N)` сравнений (где `K` — средняя длина строки для посимвольного сравнения).
3. **Дедупликация (`new Set`):** `O(N)` — вставка `N` элементов в хэш-таблицу Set и создание из неё массива обратно занимает линейное время.
4. **Объединение в строку (`slice` + `join`):** `O(N + L)` — создание среза и объединение строк требует прохода по элементам и выделения памяти под итоговую строку длиной `L`.

Таким образом, если активирована сортировка, общая временная сложность составляет **`O(N log N + L)`** (в терминах количества элементов обычно упрощают до **`O(N log N)`**). Если сортировка отключена, сложность снижается до строго линейной: **`O(N + L)`** (или **`O(N)`**).

---

## 💾 2. Пространственная сложность (Space Complexity): `O(N + L)`

1. **Создание копии массива:** Вызов `.filter()` возвращает новый массив `items`, который в худшем случае хранит те же `N` элементов. Это требует **`O(N)`** памяти.
2. **Дедупликация:** Создание `new Set(items)` и последующего массива требует временного хранения уникальных элементов — до **`O(N)`** памяти.
3. **Результирующая строка:** Возвращаемая строка имеет длину `L`, что требует выделения дополнительной памяти размера **`O(L)`**.

Итоговая пространственная сложность: **`O(N + L)`** (или **`O(N)`** относительно количества элементов).

## 🔬 3. Пошаговый разбор на примерах

### Пример А: Стандартное форматирование без лимита
```typescript
listFormat(['apple', 'banana', 'cherry'])
```
1. **Фильтрация:** `items` = `['apple', 'banana', 'cherry']`.
2. **Проверки длины:** Длина 3, пропускаем проверки `items.length === 1`.
3. **Опции:** `sorted` и `unique` не переданы.
4. **Форматирование конца списка:**
   - `firstSection` = `items.slice(0, 2).join(', ')` -> `"apple, banana"`
   - `secondSection` = `items[2]` -> `"cherry"`
   - Результат: `"apple, banana" + " and " + "cherry"` -> **`"apple, banana and cherry"`**.

---

### Пример Б: Ограничение длины (Остался 1 элемент)
```typescript
listFormat(['apple', 'banana', 'cherry'], { length: 2 })
```
1. **Фильтрация:** `items` = `['apple', 'banana', 'cherry']`.
2. **Лимит длины:** Параметр `options.length` равен `2`. Условие `options.length < items.length` выполнено (`2 < 3`).
3. **Разделение:**
   - `firstSection` = `items.slice(0, 2).join(', ')` -> `"apple, banana"`
   - Вычисление остатка: `count` = `3 - 2 = 1`.
   - `secondSection` = `1 other` (так как `count > 1` ложно, `"s"` не добавляется).
   - Результат: `"apple, banana" + " and " + "1 other"` -> **`"apple, banana and 1 other"`**.

---

### Пример В: Ограничение длины (Осталось несколько элементов)
```typescript
listFormat(['apple', 'banana', 'cherry', 'date'], { length: 2 })
```
1. **Фильтрация:** `items` = `['apple', 'banana', 'cherry', 'date']`.
2. **Лимит длины:** `options.length` равен `2`. Условие `2 < 4` выполнено.
3. **Разделение:**
   - `firstSection` = `items.slice(0, 2).join(', ')` -> `"apple, banana"`
   - Вычисление остатка: `count` = `4 - 2 = 2`.
   - `secondSection` = `2 others` (так как `count > 1` истинно, добавляется суффикс `"s"`).
   - Результат: `"apple, banana" + " and " + "2 others"` -> **`"apple, banana and 2 others"`**.

## 💡 4. Разбор ключевых строк кода (FAQ)

### Зачем нужны две проверки `items.length === 1` в разных местах?

В коде функции мы видим условие:
```typescript
// Первая проверка
if (items.length === 1) {
  return items[0];
}

// ... сортировка и уникализация ...

// Вторая проверка
if (items.length === 1) {
  return items[0];
}
```

* **Первая проверка (Early Exit):** Срабатывает сразу после фильтрации пустых элементов. Если в массиве изначально (или после очистки) был всего один элемент, нам не нужно тратить ресурсы процессора на сортировку (`items.sort()`) или создание структуры `Set` для дедупликации (`options.unique`). Мы сразу возвращаем этот элемент.
* **Вторая проверка:** Необходима потому, что операция удаления дубликатов `Array.from(new Set(items))` может уменьшить размер массива. Например, если на входе было `['apple', 'apple']`, то первая проверка её пропустит (длина 2), но после дедупликации массив превратится в `['apple']` (длина 1). Без второй проверки код пошел бы дальше и попытался разделить этот единственный элемент на `firstSection` и `secondSection`, что привело бы к некорректному результату `"" and "apple"`.

---

### Зачем делать `filter((item) => !!item)`?

Конструкция `!!item` приводит значение элемента к булевому типу (`Boolean`). Она отсекает пустые строки (`""`), а также любые другие falsy-значения (такие как `undefined`, `null` или `false`, если они случайно попали в массив аргументов с нестрогой типизацией).

Без этой фильтрации пустые элементы приводили бы к лишним запятым в выводе. Например, без фильтрации `['apple', '', 'banana']` отформатировалось бы как `"apple,  and banana"`.

---

### Как работает встроенная сортировка `sort()` в JavaScript?

По умолчанию метод `Array.prototype.sort()` сортирует элементы как строки в лексикографическом порядке (на основе значений кодовых точек UTF-16).
* **Специфика:** Заглавные буквы идут раньше строчных (например, `"Banana"` будет стоять перед `"apple"`).
* **Влияние на исходные данные:** Метод `.sort()` мутирует исходный массив. В нашей функции это безопасно, так как мы работаем со скопированным массивом `items`, полученным после вызова `.filter()`, и не изменяем оригинальный массив `itemsParam`, переданный пользователем.

## ⚠️ 5. Граничные случаи (Edge Cases)

1. **Пустой входной массив (или массив только из пустых строк):**
   После `.filter()` массив `items` имеет длину 0. Срабатывает условие `if (!items.length || items.length === 0)` и возвращается пустая строка `""`.
2. **`options.length` равен нулю или отрицательный:**
   Условие `options.length > 0` предотвращает некорректную обработку. Такой лимит будет проигнорирован, и функция вернет стандартно объединенный список.
3. **`options.length` больше или равен длине массива:**
   Например, `length: 5` при длине массива 3. Условие `options.length < items.length` вернет `false`, и функция отформатирует весь список целиком, не скрывая элементы под ярлыком `others`.
4. **Массив с одинаковыми элементами при `unique: true`:**
   Входные данные `['apple', 'apple', 'apple']` корректно дедуплицируются до `['apple']`, а затем возвращаются как `"apple"` благодаря второй проверке на длину.

## 📐 6. Итоговая карточка сложности

```
┌─────────────────────────────────────────────┐
│             Сложность listFormat            │
├─────────────────────────┬───────────────────┤
│  Временная сложность    │  O(N log N + L)   │
│  Пространственная       │  O(N + L)         │
│  Паттерн / Способ       │  Итеративный      │
└─────────────────────────┴───────────────────┘
```

* `N` — количество элементов во входном массиве.
* `L` — суммарная длина всех строковых элементов.

# `enum` против union строковых литералов для статусов

## Условие задачи

Дан компонент бейджа со статусом, типизированный через `enum`:

```typescript
enum Status {
  Idle = 'idle',
  Loading = 'loading',
  Success = 'success',
  Error = 'error',
}

function Badge({ status }: { status: Status }) {
  return <span className={status}>{status}</span>
}

// <Badge status="idle" /> — ошибка, нужен Status.Idle
```

Перепиши так, чтобы:
- статус передавался обычной строкой (`'idle'`), без импорта enum и без `Status.Idle`;
- не генерировался лишний рантайм-код для типа, который по сути — фиксированный набор строк;
- было удобно перебрать все значения (например, для рендера списка вариантов).

---

## Решение

```typescript
// union строковых литералов — нулевой рантайм, отличный инференс
type Status = 'idle' | 'loading' | 'success' | 'error'

function Badge({ status }: { status: Status }) {
  return <span className={status}>{status}</span>
}

// <Badge status="idle" /> — работает и проверяется ✅

// если нужен перебор значений — массив as const + тип из него:
const STATUSES = ['idle', 'loading', 'success', 'error'] as const
type Status2 = (typeof STATUSES)[number]
```

---

## Ключевые детали

### 1. `enum` — это не просто тип, это рантайм-объект

В отличие от `interface`/`type`, которые полностью стираются при компиляции, обычный (не `const`) `enum` компилируется в реальный JS-объект:

```javascript
var Status;
(function (Status) {
  Status['Idle'] = 'idle'
  Status['Loading'] = 'loading'
  // ...
})(Status || (Status = {}))
```

Это код, который попадает в бандл и выполняется в рантайме — лишний вес и лишняя косвенность там, где нужен был просто тип.

### 2. Union строковых литералов — нулевой рантайм

```typescript
type Status = 'idle' | 'loading' | 'success' | 'error'
```

Эта строка полностью стирается компилятором. Никакого JS-кода она не генерирует — только информацию для тайпчекера. Значение можно передавать как обычную строку, без импорта типа в рантайме.

### 3. Эргономика: строка против `Status.Idle`

С `enum` вызывающий код обязан импортировать `Status` и писать `Status.Idle`, даже если по смыслу нужна была просто строка `'idle'`. Это лишняя связанность между модулями и более многословный API. Union принимает обычные строковые литералы напрямую.

### 4. Нужен перебор значений — `as const` массив

Если из union нужно получить список значений в рантайме (например, для `.map()` по вариантам кнопки), `enum` даёт это «бесплатно» (`Object.values(Status)`), а union — нет, поскольку он не существует в рантайме. Решение — завести источник истины как массив и вывести тип из него:

```typescript
const STATUSES = ['idle', 'loading', 'success', 'error'] as const
type Status2 = (typeof STATUSES)[number] // 'idle' | 'loading' | 'success' | 'error'
```

`as const` не даёт TS расширить литералы до `string[]`, а `(typeof STATUSES)[number]` достаёт union типов элементов массива. Теперь и тип, и рантайм-список значений выводятся из одного источника — `STATUSES`.

## Частые вопросы

### А если использовать `const enum`?

`const enum` действительно стирается при компиляции (директивы инлайнятся в местах использования) — рантайм-объект не создаётся. Но у него свои подводные камни: он не работает с `isolatedModules` (Babel, esbuild, SWC не умеют его стирать корректно), плохо дружит с `--isolatedModules: true` в tsconfig и не позволяет `Object.values`. Из-за этого многие гайдлайны (включая TypeScript-команду) советуют не использовать `const enum` в проектах с современными бандлерами.

### Когда `enum` всё-таки оправдан?

Когда вам реально нужен рантайм-объект: например, если значения должны быть доступны для итерации (`Object.values(Status)`), сериализации или если это часть публичного API библиотеки, которая должна экспортировать сам объект, а не только тип.

### Чем `as const` массив лучше, чем просто `enum` для итерации?

Массив `as const` — обычный JS-массив, который дополнительно даёт точный union-тип через индексный доступ. Это легче (без обёрточного объекта enum), предсказуемо сериализуется в JSON и даёт `.map()`/`.includes()` из коробки.

## Сложность алгоритма

- **Временная сложность**: $O(1)$ — обращение к строковому литералу/элементу массива.
- **Пространственная сложность**: $O(n)$ для массива `STATUSES`, где $n$ — число статусов (фиксированная небольшая константа).

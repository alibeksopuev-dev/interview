# Типобезопасный `get(obj, key)` через `keyof`

## Условие задачи

Дан нетипизированный хелпер:

```typescript
function get(obj: any, key: string): any {
  return obj[key]
}
```

Перепиши его так, чтобы:
- тип `key` ограничивался реальными ключами `obj` (опечатка — ошибка компиляции);
- тип возврата зависел от ключа (`get(user, 'name')` → `string`, `get(user, 'age')` → `number`), а не был `any`.

---

## Решение

```typescript
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}

const user = { name: 'Ann', age: 30 }
const name = get(user, 'name') // string ✅
const age = get(user, 'age')   // number ✅
const typo = get(user, 'naem') // ошибка: 'naem' не ключ user ✅
```

---

## Ключевые детали

### 1. `K extends keyof T` — ограничение ключа

`keyof T` — это union всех имён свойств `T` (для `user` — `'name' | 'age'`). Ограничивая `K` этим union, компилятор отказывается принимать ключ, которого нет в объекте.

```typescript
type UserKeys = keyof typeof user // 'name' | 'age'
```

### 2. `T[K]` — индексный доступ как тип возврата

`T[K]` читает тип значения по конкретному ключу `K`. Поскольку `K` — это generic-параметр (а не конкретный литерал), `T[K]` тоже остаётся generic-выражением: для каждого вызова с конкретным `K` оно вычисляется в конкретный тип (`string`, `number`, ...).

### 3. Порядок вывода типов

При вызове `get(user, 'name')`:
1. `T` выводится из первого аргумента → `{ name: string; age: number }`.
2. `K` выводится из второго аргумента → литерал `'name'`.
3. Компилятор проверяет, что `'name' extends keyof T` — да.
4. Тип возврата вычисляется как `T['name']` → `string`.

### 4. Почему это лучше, чем перегрузки

Можно было бы написать перегрузки под каждое поле (`get(obj, 'name'): string` и т.д.), но это не масштабируется — для каждого нового поля нужна новая перегрузка. Generic-версия работает для **любого** объекта и любого его ключа без дублирования кода.

## Частые вопросы

### Почему `key: string` в исходной версии — это плохо?

`string` разрешает передать любую строку, включая несуществующий ключ (`'naem'`). Ошибка проявится только в рантайме (`undefined`), а не на этапе компиляции.

### Можно ли расширить `get` на вложенный доступ (`get(user, 'profile.city')`)?

Да, но это требует более сложного типа — рекурсивного разбора строки по точкам через template literal types и `infer`. Это отдельная, более сложная задача (см. `ts-template-literal` и подобные).

### А если `obj` — `Record<string, unknown>`?

Тогда `keyof T` — это `string`, и ограничение `K extends keyof T` ничего не даёт (любая строка проходит). Типобезопасность `get` максимальна именно на объектах с конкретными полями.

---

## Сложность алгоритма

- **Временная сложность**: $O(1)$ — обычное обращение по индексу.
- **Пространственная сложность**: $O(1)$.

# Графика в браузере: от Canvas до Three.js — план изучения для новичка

Это сопроводительный гайд к интерактивному showcase'у на странице `/graphics`. Цель — не дать тебе "энциклопедию", а провести **по шагам**, объясняя каждую технологию простым языком: что это, зачем, как работает внутри.

## 📍 Где мы и куда идём

В вебе для рисования "пиксельной" графики (не HTML/CSS!) есть **4 технологии**:

```
┌─────────────────────────────────────────────────────────────┐
│  Canvas 2D  →  PixiJS  →  WebGL (raw)  →  Three.js          │
│   простой      быстрый    мощный, но       3D через         │
│   2D API       2D-движок  низкоуровневый   обёртку          │
└─────────────────────────────────────────────────────────────┘
       │            │            │              │
       └────────────┴────────────┴──────────────┘
                все они рисуют в один и тот же <canvas>!
```

Все они работают через тег `<canvas>` в HTML. Просто разные **способы управлять им** из JS. Canvas 2D — самый простой, WebGL — самый низкоуровневый и мощный, Three.js и PixiJS — обёртки поверх WebGL для удобства.

## 🎯 План обучения — 4 недели по 1-2 часа в день

### Неделя 1: Canvas 2D — основы рисования

Это твоя стартовая точка. Без понимания Canvas 2D остальное не зайдёт.

**День 1-2: Базовый API**
- Открой карточку №1 в showcase'е (`Canvas 2D — рисуем как в Paint`).
- Поэкспериментируй: меняй цвета, размеры, добавь свои фигуры.
- Изучи в MDN: `fillRect`, `strokeRect`, `arc`, `beginPath`, `moveTo`, `lineTo`, `fill`, `stroke`.
- **Ключевая мысль**: Canvas 2D — это **immediate mode**. Нарисовал → забыл. Объектов в памяти нет. Хочешь подвинуть круг? Сотри весь canvas и нарисуй заново.

**День 3-4: Анимация**
- Карточка №2 (`requestAnimationFrame`).
- Пойми **цикл рендера**: на каждом кадре `clear → update → draw`.
- Заучи как мантру: `requestAnimationFrame`, а не `setInterval`.
- Состояние держим **вне React state** (в `useRef` или в замыкании внутри `useEffect`), иначе ре-рендеры убьют производительность.

**День 5-7: Интерактив**
- Карточка №3 (рисовалка).
- Главный приём — координаты мыши **внутри canvas** через `getBoundingClientRect()`.
- Рисуй **линии между точками**, а не точки — иначе на быстром движении получишь пунктир.
- Pointer Events (`pointerdown/move/up`) удобнее Mouse Events: работают для touch и для пера.

**Контрольное задание недели:**
> Сделай Snake (змейка) на Canvas 2D. Сетка 20×20, змея ест еду и удлиняется, на стенке умирает. Управление со стрелок.

### Неделя 2: PixiJS — когда Canvas 2D становится тесно

**Зачем переходить на Pixi:**
Когда нужно много объектов (>1000 на экране) — Canvas 2D начинает лагать. Pixi решает это за счёт **батчинга**: вместо тысячи команд "нарисуй кружок" одна большая команда уезжает на GPU.

**День 1-2: Знакомство**
- Карточка №4 (основы Pixi).
- Главные сущности:
  - `Application` — обёртка вокруг canvas и render loop'а.
  - `Container` — узел сцены (как `<div>` в DOM).
  - `Graphics` — для примитивов (прямоугольники, круги).
  - `Sprite` — для текстур (картинок).
  - `Text` — для текста.
- В Pixi **retained mode**: каждый объект "живёт" в памяти. Меняешь `obj.x = 100` — оно само перерисуется в следующем кадре.

**День 3-4: Дерево сцены**
- Создай `Container`, положи в него несколько `Graphics`. Подвинь контейнер — двинутся все дети. Это как `transform` на родительском `<div>`.
- У каждого объекта есть `x, y, rotation, scale, alpha, tint`.

**День 5-6: События**
- `obj.eventMode = 'static'` (обязательно!) + `obj.on('pointerdown', ...)`.
- Pixi считает hit-test'ы сам — не нужно вычитать координаты мыши.

**День 7: Производительность**
- Карточка №5 (5000 частиц).
- Пойми разницу между `Container` и `ParticleContainer` (для миллионов объектов).
- Sprite дешевле, чем Graphics: если 10 000 одинаковых иконок — сделай одну текстуру и расставь Sprite'ы.

**Контрольное задание недели:**
> Сделай "падающие конфетти" по клику: 200 частиц вылетают из точки клика, падают с гравитацией, постепенно становятся прозрачными и удаляются. Должно работать в 60 fps даже если кликнуть 50 раз подряд.

### Неделя 3: WebGL — спускаемся на GPU

⚠️ **Самая сложная неделя.** Здесь твой мозг будет ломаться. Это нормально.

**Что нужно понять прежде всего:**

WebGL — это **НЕ "продвинутый Canvas 2D"**. Это **совсем другая модель работы**:

| Canvas 2D | WebGL |
|-----------|-------|
| Ты говоришь: "нарисуй прямоугольник тут" | Ты загружаешь массив вершин в видеокарту |
| Браузер делает всё | Ты сам пишешь программу для GPU (шейдер) |
| Координаты в пикселях, (0,0) в углу | Координаты -1..+1, (0,0) в центре, Y вверх |
| Простой, но "потолок" — тысячи объектов | Сложный, но миллионы вершин в 60 fps |

**День 1-2: Концепция шейдеров**
- Открой карточку №6 (Hello Triangle).
- Прочитай код **5 раз**. Каждый раз будет понятнее.
- Главное:
  - **Vertex shader** — мини-программа, которая считает позицию **каждой вершины**. Запускается N раз (N = число вершин).
  - **Fragment shader** — мини-программа, которая считает цвет **каждого пикселя**. Запускается ОЧЕНЬ много раз (на 460×300 canvas → 138 000 раз за кадр).
  - GPU запускает их **параллельно** — отсюда скорость.

**День 3-4: Boilerplate WebGL**
- 90% кода WebGL — это шаги:
  1. Скомпилировать шейдеры (`gl.compileShader`).
  2. Слинковать в программу (`gl.linkProgram`).
  3. Создать буфер с вершинами (`gl.createBuffer`, `gl.bufferData`).
  4. Сказать "как читать буфер" (`gl.vertexAttribPointer`).
  5. Нарисовать (`gl.drawArrays`).
- Это **повторяется в каждом WebGL-проекте**. Заучи как ритуал.

**День 5-6: Uniforms и шейдер-арт**
- Карточка №7 (анимированный шейдер).
- **Uniform** — переменная, общая для всех вершин/пикселей этого кадра.
- Передаём `u_time` → каждый кадр считаем новый цвет в shader'е.
- Это техника, на которой работает [Shadertoy](https://www.shadertoy.com/). Полистай — там тысячи примеров.

**День 7: GLSL — язык шейдеров**
- Это C-подобный язык. Типы: `float, vec2, vec3, vec4, mat4`.
- Функции: `sin, cos, length, mix, smoothstep, step`.
- Прочитай первую главу "[The Book of Shaders](https://thebookofshaders.com)" — там очень доходчиво.

**Контрольное задание недели:**
> Напиши свой fragment shader, который рисует круг в центре canvas с плавным контуром (anti-aliasing через smoothstep).

### Неделя 4: Three.js — 3D без боли

После WebGL это будет ощущаться как **отдых**. Three.js прячет всю боль с шейдерами.

**День 1-2: Анатомия сцены**
- Карточка №8 (3D-куб).
- Запомни **5 обязательных вещей**:
  1. `Scene` — контейнер.
  2. `Camera` — точка зрения.
  3. `Renderer` — то, что рисует.
  4. `Mesh = Geometry + Material` — объект.
  5. `Light` — свет. **БЕЗ СВЕТА ВСЁ ЧЁРНОЕ** (для PBR-материалов). Это вопрос на интервью.

**День 3-4: Координаты и трансформации**
- Three.js: X вправо, Y **вверх**, Z **на тебя**.
- У каждого Mesh'а есть `position`, `rotation` (в радианах!), `scale`.
- `mesh.position.set(1, 0, 0)` или `mesh.position.x = 1` — оба работают.

**День 5: Камера и lookAt**
- `PerspectiveCamera(fov, aspect, near, far)` — самая частая.
- `camera.position.set(0, 2, 5)` + `camera.lookAt(0, 0, 0)` — стандарт.
- Если резайзишь canvas: обнови `camera.aspect` и **обязательно вызови** `camera.updateProjectionMatrix()`. Без этого картинка будет растянута.

**День 6: Интерактив**
- Карточка №9 (drag-to-rotate).
- Lerp (линейная интерполяция) для плавных анимаций:
  ```js
  current += (target - current) * 0.1
  ```
- Для серьёзных вьюверов — `OrbitControls` из `three/examples/jsm/controls/OrbitControls.js`. Бесплатно даёт pan/zoom/инерцию.

**День 7: react-three-fiber**
- Это обёртка Three.js для React. Вместо императивного кода — JSX:
  ```jsx
  <Canvas>
    <ambientLight intensity={0.5} />
    <mesh rotation={[0, 0.5, 0]}>
      <boxGeometry args={[1, 1, 1]} />
      <meshStandardMaterial color="hotpink" />
    </mesh>
  </Canvas>
  ```
- Идеальна для React-проектов. Под капотом — тот же Three.js.

**Контрольное задание недели:**
> Сделай 3D-вьювер: загрузи GLTF-модель (можешь скачать любую с [sketchfab.com](https://sketchfab.com)), добавь свет, OrbitControls. Должно работать через trackpad.

## 🧠 Базовые концепции — на пальцах

### 1. Что такое canvas

```html
<canvas width="800" height="600"></canvas>
```

Это просто **прямоугольный битмап** в DOM. По умолчанию — пустой и прозрачный. Сам по себе он не делает ничего. Чтобы рисовать, ты получаешь у него **контекст**:

```js
const ctx2d = canvas.getContext('2d')        // → Canvas 2D
const gl    = canvas.getContext('webgl')     // → WebGL
const gl2   = canvas.getContext('webgl2')    // → WebGL 2
const gpu   = canvas.getContext('webgpu')    // → WebGPU (новый, не везде)
```

⚠️ **У одного canvas — только один контекст за всё время жизни.** Получил 2d → нельзя потом получить webgl на том же canvas. Если нужно — создай два разных canvas.

### 2. CSS-размер vs ширина битмапа

Классическая ловушка:

```html
<canvas width="200" height="100" style="width: 800px; height: 400px"></canvas>
```

Здесь:
- **Битмап** — 200×100 пикселей (это разрешение, в нём ты рисуешь).
- **На экране** — 800×400 пикселей (это CSS, размер визуально).
- → картинка будет **растянута и размыта**.

**Правило**: размер битмапа = `element.clientWidth * devicePixelRatio`. На retina это в 2 раза больше CSS-пикселей.

```js
const dpr = window.devicePixelRatio || 1
canvas.width  = canvas.clientWidth  * dpr
canvas.height = canvas.clientHeight * dpr
ctx.scale(dpr, dpr)  // чтобы продолжать рисовать в CSS-пикселях
```

В PixiJS и Three.js это делается одной опцией (`autoDensity: true` / `setPixelRatio`).

### 3. Цикл рендера (game loop)

В любой анимации/игре в browser'е сердце — это:

```js
function tick() {
  update()  // обновили физику, ввод, AI
  draw()    // нарисовали кадр
  requestAnimationFrame(tick)  // запросили следующий
}
requestAnimationFrame(tick)
```

`requestAnimationFrame`:
- Синхронизирован с vsync экрана (обычно 60 Гц).
- Останавливается, когда вкладка не активна — экономит батарею.
- Принимает timestamp в параметре — используй его для delta time.

```js
let last = performance.now()
function tick(now) {
  const dt = (now - last) / 1000  // секунд с прошлого кадра
  last = now
  player.x += player.vx * dt  // движение в "юнитах в секунду"
  requestAnimationFrame(tick)
}
```

**Почему через `dt`, а не просто `player.x += 1`?** Чтобы скорость не зависела от FPS. Если у пользователя 144 Гц монитор — кадров будет 144, не 60, и без `dt` объекты у него будут лететь быстрее.

### 4. Системы координат — главная путаница

| Технология | (0, 0) | Y растёт | Единицы |
|------------|--------|----------|---------|
| Canvas 2D | левый верх | **вниз** | пиксели |
| PixiJS | левый верх | **вниз** | пиксели |
| WebGL | **центр** | **вверх** | -1..+1 (NDC) |
| Three.js | центр (мира) | **вверх** | "мировые единицы" (метры по соглашению) |

Когда переходишь между ними — этот пункт ломает всем мозг. **Запомни таблицу.**

### 5. Шейдеры — на самом простом языке

Представь, что ты — GPU, и тебе дали задачу:
> Нарисуй треугольник.

Тебе сказали:
> Вот 3 точки в пространстве. И вот 2 программы.
>
> Программа A — это **vertex shader**. Для каждой из 3 точек выполни её один раз. Эта программа скажет тебе, где эта точка должна оказаться на экране.
>
> Программа B — это **fragment shader**. Для каждого пикселя ВНУТРИ треугольника выполни её один раз. Эта программа скажет тебе, какого цвета должен быть этот пиксель.

То есть GPU **запускает твой код миллионы раз параллельно**. Vertex shader — мало раз (по числу вершин). Fragment shader — много раз (по числу пикселей).

Это и есть вся "магия" WebGL/Three.js.

### 6. Геометрия и материал — кирпичики 3D

В Three.js (и большинстве 3D-движков):

```js
const mesh = new Mesh(geometry, material)
```

- **Geometry** — это форма: набор точек (вершин) и инструкция "как их соединять в треугольники". Сферы, кубы, торы — это всё геометрии.
- **Material** — это "из чего сделана поверхность". Глянцевый или матовый? Какого цвета? Текстурированный?
- **Mesh** — это форма + материал, готовая к рендеру.

Один и тот же `BoxGeometry` можно использовать с разными материалами. Один и тот же материал — с разными геометриями. Это сильная модель переиспользования.

## ⚡️ Что почти наверняка спросят на интервью

1. **Canvas vs SVG vs WebGL — когда что?**
   - SVG — иконки, диаграммы, до ~1000 элементов, DOM-события на каждом.
   - Canvas 2D — сотни-тысячи объектов, простая 2D-графика.
   - WebGL — миллионы вершин, кастомные шейдеры.
   - PixiJS — десятки тысяч 2D-объектов (Pixi решает 2D, что Three.js — 3D).

2. **Зачем `requestAnimationFrame` вместо `setInterval`?**
   - Синхронизация с vsync.
   - Остановка в неактивной вкладке.
   - Single source of truth для кадров.

3. **Что такое vertex shader и fragment shader?**
   - Vertex: программа, которая считает позицию вершины.
   - Fragment: программа, которая считает цвет пикселя.
   - Обе крутятся на GPU параллельно.

4. **Почему Three.js материал может оказаться чёрным?**
   - Нет света в сцене (для `MeshStandardMaterial`, `MeshLambertMaterial`).
   - `MeshBasicMaterial` свет не требует — используй для отладки.

5. **Что такое device pixel ratio?**
   - Соотношение физических пикселей к CSS-пикселям. На retina = 2.
   - Если не учесть → canvas размыт на retina.

6. **Что такое layout thrashing — и как он связан с canvas?**
   - Чтение `getBoundingClientRect()` форсирует layout.
   - Если перед каждой записью в canvas читаешь его размер → reflow на каждом кадре.
   - Решение: измерь один раз через `ResizeObserver`, кэшируй.

7. **Чем `getBoundingClientRect().width` отличается от `offsetWidth` под `transform: scale`?**
   - `getBoundingClientRect` учитывает transform → даёт визуальный размер.
   - `offsetWidth` — нет → даёт исходный размер.

8. **Утечка GPU-памяти в Three.js — как избежать?**
   - При unmount: `renderer.dispose()`, `geometry.dispose()`, `material.dispose()`, `texture.dispose()`.
   - Pixi: `app.destroy(true, { children: true })`.

9. **immediate mode vs retained mode?**
   - Immediate: Canvas 2D. Команды → пиксели → забыли. Объектов нет.
   - Retained: PixiJS, Three.js, DOM. Объекты живут в памяти, движок сам перерисовывает.

10. **WebGL vs WebGPU?**
    - WebGL основан на OpenGL ES (старый стандарт, 1990-е → 2000-е).
    - WebGPU — новое API, работает на Vulkan/Metal/DX12. В 2026 поддерживается уже в большинстве браузеров.
    - В новых проектах смотреть на WebGPU имеет смысл, но WebGL ещё долго будет жить.

## 🎓 Финальные советы новичку

1. **Не пытайся учить всё сразу.** Если ты сейчас на Canvas 2D — не лезь в шейдеры. Каждая ступенька опирается на предыдущую.
2. **Пиши код, не смотри видосы.** Открой showcase, переписывай каждый пример руками, ломай его специально, смотри что произойдёт.
3. **Лучший учитель — баги.** Когда у тебя что-то не работает — это и есть момент, когда ты учишься. Гугли, читай ошибки, экспериментируй.
4. **Не бойся "уродливого" кода поначалу.** Сначала пусть работает, потом причесать.
5. **Маленькие проекты > большие.** Лучше 10 микро-демок (рисовалка, snake, particle system, 3D-куб), чем один незаконченный grand project.

Удачи! Каждая карточка в showcase'е — это отдельный мини-урок. Иди по порядку, и через месяц будешь свободно говорить на собеседовании о всех 4 технологиях.

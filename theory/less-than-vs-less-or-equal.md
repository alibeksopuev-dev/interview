# `<` vs `<=` (и `>` vs `>=`) в циклах и условиях

Раз и навсегда: **выбор между строгим (`<`, `>`) и нестрогим (`<=`, `>=`) сравнением — это вопрос "какое последнее значение я хочу обработать?"**. Всё остальное — следствие.

---

## Главное правило одной фразой

> Спроси себя: **"Какой самый последний индекс/элемент я должен включить?"**
> Если последнее значение, которое ты хочешь обработать, — это то, что стоит **справа** от знака → нужен `<=` / `>=`.
> Если последнее значение — на **единицу меньше** того, что справа → нужен `<` / `>`.

---

## 1. Классика: перебор массива по индексу

Массив с длиной `n` имеет **индексы от `0` до `n - 1`**. Элемента с индексом `n` не существует.

```ts
const arr = [10, 20, 30]  // length = 3, индексы: 0, 1, 2
```

### Правильно — `<`

```ts
for (let index = 0; index < arr.length; index++) {
  console.log(arr[index]) // 10, 20, 30
}
```

Почему `<`, а не `<=`? Потому что справа стоит `arr.length` (= 3), а **последний реальный индекс = 2**. Он на единицу меньше длины → строгий `<`.

### Ошибка — `<=`

```ts
for (let index = 0; index <= arr.length; index++) {
  console.log(arr[index]) // 10, 20, 30, undefined ← лишняя итерация!
}
```

`index` дойдёт до `3`, а `arr[3]` не существует → `undefined`. Это классический **off-by-one** баг.

**Мнемоника:** `length` — это *количество*, а не *последний индекс*. С `.length` почти всегда `<`.

### Реальный пример из проекта — [myFilter/myFilter.ts](../myFilter/myFilter.ts#L27)

```ts
const arrayLength = this.length

for (let index = 0; index < arrayLength; index++) {
  if (Object.hasOwn(this, index) && callbackFn.call(thisArg, this[index], index, this)) {
    array.push(this[index])
  }
}
```

Здесь `< arrayLength` — потому что мы хотим обойти индексы `0 … length-1`. Если бы стояло `<=`, мы бы обратились к `this[length]` (несуществующая ячейка) и сломали разреженную логику.

## 2. Когда нужен именно `<=`: работа с индексами напрямую

`<=` появляется, когда справа стоит уже **сам последний индекс**, а не длина.

### Пример из проекта — [binarySearch/binarySearch.ts](../binarySearch/binarySearch.ts#L18-L22)

```ts
let leftIndex = 0
let rightIndex = arr.length - 1  // ← это ПОСЛЕДНИЙ индекс, а не длина!

while (leftIndex <= rightIndex) {
  const midIndex = leftIndex + Math.floor((rightIndex - leftIndex) / 2)
  // ...
}
```

Здесь два ключевых момента:

**а) `rightIndex = arr.length - 1`** — мы заранее вычли единицу, поэтому справа теперь настоящий последний индекс.

**б) `while (leftIndex <= rightIndex)`** — почему `<=`, а не `<`?

Потому что диапазон `[leftIndex, rightIndex]` **включает оба конца**. Когда `leftIndex === rightIndex`, остался ровно **один непроверенный элемент**, и его обязательно надо проверить.

Если поставить `<`:

```ts
while (leftIndex < rightIndex) { ... }  // ❌ БАГ
```

то в момент, когда границы сойдутся в одну точку, цикл прервётся, **не проверив последний элемент**. Тесты вроде `binarySearch([42], 42)` вернут `-1` вместо `0`.

> **Правило диапазонов:** если границы **включительные** (оба конца — валидные значения, `[a, b]`) → условие продолжения `a <= b`.
> Если граница **исключительная** (`[a, b)`, правый конец не входит) → условие `a < b`.

Бинарный поиск использует включительный диапазон `[left, right]`, отсюда `<=`.

## 3. Таблица-шпаргалка

| Что справа от знака | Что хочешь обработать | Знак | Пример |
|---|---|---|---|
| `arr.length` | индексы `0 … length-1` | `<` | `for (i = 0; i < arr.length; i++)` |
| `arr.length - 1` | тот же последний индекс | `<=` | `while (left <= right)` |
| число `n` (нужны `1..n`) | включая `n` | `<=` | `for (i = 1; i <= n; i++)` |
| число `n` (нужны `0..n-1`) | не включая `n` | `<` | `for (i = 0; i < n; i++)` |
| граница `[a, b)` | правый конец НЕ входит | `<` | срезы, полуинтервалы |
| граница `[a, b]` | оба конца входят | `<=` | бинарный поиск |

## 4. Симметрично для `>` и `>=` (обратный цикл)

Всё то же самое, только зеркально. Идём с конца массива:

```ts
// Обход массива справа налево
for (let index = arr.length - 1; index >= 0; index--) {
  console.log(arr[index]) // 30, 20, 10
}
```

Почему `>= 0`, а не `> 0`?

Потому что индекс `0` — **валидный, самый первый элемент**, его надо обработать. С `> 0` цикл остановится на `index === 1` и **пропустит первый элемент**.

```ts
for (let index = arr.length - 1; index > 0; index--) {
  console.log(arr[index]) // 30, 20 ← 10 потеряли! ❌
}
```

**Правило:** если нижняя граница — валидное значение (обычно `0`), нужен `>=`.

## 5. Практический чек-лист (задавай себе 3 вопроса)

Когда сомневаешься между `<` и `<=`:

1. **Что стоит справа от знака — количество (`length`, `n`) или индекс (`length - 1`, последний элемент)?**
   - Количество → скорее всего `<`
   - Индекс → скорее всего `<=`

2. **Последнее значение, которое я хочу обработать, входит в диапазон?**
   - Да, входит → `<=`
   - Нет, это "стоп-граница" → `<`

3. **Проверь на крайнем случае руками:** массив из 1 элемента (`[x]`) или пустой (`[]`).
   - Прогони цикл мысленно на `length = 1`. Если обработался лишний/недостающий элемент — знак выбран неверно.

## 6. Частые места, где путаются

### Границы окна / two pointers

```ts
let left = 0
let right = arr.length - 1

while (left < right) {   // ← здесь < правильно!
  // сравниваем ПАРУ (left, right), нужны два РАЗНЫХ элемента
  // когда left === right — пара схлопнулась, работать не с чем
}
```

Тут `<` (а не `<=` как в бинарном поиске!), потому что мы обрабатываем **пару разных элементов**. Когда указатели встречаются — пары больше нет.

**Вывод:** знак зависит не от типа задачи, а от того, **нужен ли тебе момент `left === right`**:
- бинарный поиск: да, там ещё есть 1 элемент для проверки → `<=`
- two pointers (пара): нет, пара исчезла → `<`

### Диапазон чисел "от 1 до n включительно"

```ts
// Сумма 1 + 2 + ... + n
let sum = 0
for (let i = 1; i <= n; i++) {  // ← <= потому что n ДОЛЖНО войти
  sum += i
}
```

---

## TL;DR

- **`.length` → `<`** (длина = количество, последний индекс на 1 меньше)
- **`.length - 1` / включительный диапазон `[a, b]` → `<=`**
- **`>= 0`** при обходе с конца (ноль — валидный индекс)
- **two pointers на пару → `<`** (момент встречи бесполезен)
- **бинарный поиск → `<=`** (в точке встречи ещё есть элемент)
- Сомневаешься? **Прогони на массиве из 1 элемента** — off-by-one сразу вылезет.

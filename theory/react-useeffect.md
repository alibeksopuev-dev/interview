# React: Хук useEffect

`useEffect` — это основной инструмент для работы с побочными эффектами (side effects) в функциональных компонентах. Он позволяет выполнять код после рендеринга.

---

## 1. Функция очистки (Cleanup function)

Если вы возвращаете функцию из `useEffect`, React называет её **функцией очистки**.

```javascript
useEffect(() => {
  const timeoutID = setTimeout(() => {
    console.log('Действие!');
  }, 1000);

  // Возвращаемая функция — очистка
  return () => {
    clearTimeout(timeoutID);
  };
}, [value]);
```

### Когда она запускается?
1.  **Перед следующим запуском эффекта:** Если зависимости изменились, React сначала выполнит очистку *предыдущего* эффекта, а затем запустит *новый* эффект.
2.  **При размонтировании (unmount):** Когда компонент удаляется из DOM, очистка запускается в последний раз.

### Зачем она нужна?
Для предотвращения утечек памяти и нежелательного поведения:
*   Сброс таймеров (`clearTimeout`, `clearInterval`).
*   Отмена сетевых запросов (`AbortController`).
*   Удаление слушателей событий (`removeEventListener`).
*   Отписка от веб-сокетов или внешних сторов.

## 2. Массив зависимостей (Dependency Array)

Поведение эффекта меняется в зависимости от второго аргумента:

### Сценарий А: Массив не указан
```javascript
useEffect(() => {
  console.log('Запуск после КАЖДОГО рендера');
});
```
Эффект срабатывает после любого изменения стейта или пропсов в компоненте. Обычно это неэффективно и может привести к бесконечным циклам, если внутри эффекта менять стейт.

### Сценарий Б: Пустой массив `[]`
```javascript
useEffect(() => {
  console.log('Только при монтировании (Mount)');
  
  return () => {
    console.log('Только при размонтировании (Unmount)');
  };
}, []);
```
Эффект запускается один раз. Это аналог `componentDidMount` и `componentWillUnmount`. Идеально для инициализации данных.

### Сценарий В: С зависимостями `[a, b]`
```javascript
useEffect(() => {
  console.log('Mount + при изменении a или b');
}, [a, b]);
```
Эффект запустится при первом появлении и каждый раз, когда изменится `a` или `b`.

---

## 3. Как React понимает, что зависимость изменилась?

React использует алгоритм **Shallow Comparison (поверхностное сравнение)** через `Object.is`.

*   **Примитивы (string, number, boolean):** Сравниваются по значению. `5 === 5` — эффект не запустится.
*   **Ссылочные типы (object, array, function):** Сравниваются по **ссылке**. 
    *   Если вы создаете новый объект `{}` или массив `[]` внутри компонента при каждом рендере, ссылка всегда будет новой.
    *   **Следствие:** Эффект будет запускаться на каждый рендер, даже если «содержимое» объекта не поменялось. Для решения используйте `useMemo` или `useCallback`.

## 4. Практические примеры

### А. Запрос данных с отменой (Cleanup + AbortController)
Это стандартный паттерн, чтобы избежать "гонки условий" (race conditions), когда запрос завершается после того, как компонент уже размонтирован.

```tsx
useEffect(() => {
  const controller = new AbortController();

  const fetchData = async () => {
    try {
      const response = await fetch(`https://api.example.com/data/${id}`, {
        signal: controller.signal
      });
      const data = await response.json();
      setData(data);
    } catch (err) {
      if (err.name !== 'AbortError') {
        console.error('Ошибка:', err);
      }
    }
  };

  fetchData();

  // Очистка: если id изменится раньше, чем придет ответ,
  // старый запрос будет отменен.
  return () => controller.abort();
}, [id]);
```

### Б. Слушатели событий (Window Listeners)
Если не удалять слушатель, они будут накапливаться при каждом ререндере или переходе между страницами.

```tsx
useEffect(() => {
  const handleResize = () => {
    setWindowWidth(window.innerWidth);
  };

  window.addEventListener('resize', handleResize);

  // Обязательная очистка
  return () => {
    window.removeEventListener('resize', handleResize);
  };
}, []); // [] — подписываемся только один раз при старте
```

### В. Синхронизация с LocalStorage
Используется для сохранения состояния между перезагрузками страницы.

```tsx
useEffect(() => {
  localStorage.setItem('theme', theme);
}, [theme]); // Срабатывает только когда тема меняется
```

### Г. Таймеры и Debounce (то, что мы обсуждали)
Позволяет выполнять действие только после того, как пользователь закончил ввод.

```tsx
useEffect(() => {
  const timer = setTimeout(() => {
    saveToDatabase(inputValue);
  }, 500);

  return () => clearTimeout(timer);
}, [inputValue]);
```

## 📋 Итоговая таблица

| Массив зависимостей | Когда запускается эффект? | Когда запускается очистка? |
| :--- | :--- | :--- |
| **Отсутствует** | Каждый рендер | Перед новым эффектом + unmount |
| **Пустой `[]`** | Только Mount | Только Unmount |
| **С данными `[v]`** | Mount + изменение `v` | Перед новым эффектом (если `v` изменился) + unmount |

> **Правило:** Всегда указывайте в массиве **все** переменные из области видимости компонента, которые используются внутри эффекта. Иначе вы столкнетесь с проблемой "замыкания на старые данные" (stale closures).

# Реализация `Array.prototype.myConcat`

## Условие задачи

Реализовать метод `myConcat` на прототипе `Array`, который ведёт себя идентично нативному `Array.prototype.concat`:
- Возвращает **новый** массив, состоящий из элементов получателя (`this`), за которыми следуют элементы каждого переданного аргумента (слева направо).
- Аргументы-массивы «раскрываются» (flatten) ровно **на один уровень**.
- Аргументы-не-массивы добавляются как единичные значения.
- Получатель **не мутируется**.
- Копирование **поверхностное** (shallow): вложенные объекты и массивы попадают в результат по ссылке.

---

## Реализация

```typescript
export {}

declare global {
  interface Array<T> {
    myConcat<U>(...items: Array<U | Array<U>>): Array<T | U>
  }
}

Array.prototype.myConcat = function <T>(this: T[], ...items: any[]): any[] {
  // Поверхностная копия получателя (this) — база результата.
  const newArray = [...this]

  for (let i = 0; i < items.length; i++) {
    if (Array.isArray(items[i])) {
      // Массив «раскрывается» ровно на один уровень
      newArray.push(...items[i])
    } else {
      // Не-массив добавляется как одно значение
      newArray.push(items[i])
    }
  }

  return newArray
}
```

## Анализ решения: насколько оно правильное

**Вердикт: решение корректное** для практически значимого подмножества сценариев: конкатенация примитивов и массивов, поверхностность копии, отсутствие мутации получателя, раскрытие ровно на один уровень.

Отличия от нативного `concat`, которые на собеседовании стоит просто назвать вслух (реализовывать их обычно не требуют):

| Деталь спецификации | Нативный `concat` | Данная реализация |
|---|---|---|
| `Symbol.isConcatSpreadable` | Учитывается: объект с этим флагом раскрывается, массив с `false` — нет | Не учитывается: решение принимает только `Array.isArray` |
| Приведение `this` | `ToObject(this)` — работает на array-like через `.call()` | Полагается на то, что `this` — настоящий массив (спред требует итерируемости) |
| Дыры в получателе | Сохраняются | Сохраняются ✅ (спред массива копирует индексы как есть) |
| Дыры в аргументах-массивах | Сохраняются | Превращаются в `undefined` (спред итерирует и отдаёт `undefined`) |
| Ограничение длины | `TypeError` при превышении $2^{53}-1$ | Не проверяется |

Единственная реальная неточность в типичных тестах — обработка дыр **внутри аргументов-массивов**. `[1].concat([, 2])` даёт `[1, <1 empty item>, 2]`, а `push(...[, 2])` даст `[1, undefined, 2]`. Если требуется точное поведение, аргументы-массивы надо копировать поэлементно через `Object.hasOwn` (см. раздел «Точная версия по спецификации»).

## Пошаговый разбор построчно

```typescript
export {}
```
Делает файл ES-модулем. Без этого `declare global` невозможен: в скриптовом (не модульном) файле объявления и так попадают в глобальную область, и `declare global` там запрещён.

```typescript
declare global {
  interface Array<T> {
    myConcat<U>(...items: Array<U | Array<U>>): Array<T | U>
  }
}
```
Декларативное слияние (declaration merging): дописываем метод в глобальный интерфейс `Array<T>`. Каждый аргумент — это либо одиночное значение `U`, либо массив таких значений `Array<U>`; результат — массив из элементов получателя `T` и добавленных `U`. Именно так типизирован нативный `concat` в `lib.es5.d.ts` (через `ConcatArray<T>`).

```typescript
Array.prototype.myConcat = function <T>(this: T[], ...items: any[]): any[] {
```
Именно `function`, а не стрелочная функция — нужен собственный `this` (текущий массив). Стрелка захватила бы `this` из внешней области и метод бы не работал.

`...items` — rest-параметр: `concat` принимает произвольное число аргументов. В отличие от `myReduce`, `arguments` здесь не нужен: различать «не передан» и «передан `undefined`» не требуется — `undefined` просто добавляется как обычное значение.

```typescript
  const newArray = [...this]
```
Поверхностная копия получателя. Три важных следствия:
- Результат — **новый** массив, поэтому получатель не мутируется.
- Копия поверхностная: вложенные объекты копируются **по ссылке**, а не клонируются.
- Элементы получателя всегда идут в результате **первыми**, независимо от аргументов.

```typescript
  for (let i = 0; i < items.length; i++) {
```
Аргументы обрабатываются строго **слева направо** — порядок в результате повторяет порядок вызова.

```typescript
    if (Array.isArray(items[i])) {
      newArray.push(...items[i])
```
`Array.isArray` — единственный критерий «раскрывать или нет». Спред раскрывает **ровно один уровень**: элементы массива-аргумента добавляются по одному, но их собственное внутреннее устройство не трогается. Поэтому `[[6]]` отдаёт в результат сам `[6]` как один элемент.

```typescript
    } else {
      newArray.push(items[i])
    }
```
Всё, что не массив (числа, строки, `null`, `undefined`, объекты, `Set`, `Map`), добавляется как **одно** значение, без попытки итерировать.

```typescript
  return newArray
}
```
Возвращаем новый массив. Для `[1, 2].myConcat()` (без аргументов) цикл не выполнится ни разу, и вернётся поверхностная копия `[1, 2]` — как в нативном методе.

## Ключевые детали

### 1. Раскрытие ровно на один уровень (не рекурсивно)

Соблазнительно написать рекурсивный хелпер, который «раскрывает всё», но это **ошибка**: `concat` — не `flat(Infinity)`.

```typescript
[1, 2].myConcat([[6]])       // [1, 2, [6]]     ✅ верно
// рекурсивная «flatten»-версия дала бы [1, 2, 6]  ❌ неверно
```

Правило простое: раскрывается только **сам аргумент**, если он массив. Его содержимое дальше не разбирается.

### 2. Почему `Array.isArray`, а не `instanceof Array`

`Array.isArray` корректно работает с массивами из другого realm (например, из `iframe` или `vm`-контекста), где `instanceof Array` вернёт `false`, так как прототипы разные. Нативный `concat` в спецификации использует `IsArray`, поэтому `Array.isArray` — точное соответствие.

### 3. Поверхностность копии (shallow)

`myConcat` не клонирует вложенные структуры:

```typescript
const obj = { a: 1 }
const result = [obj].myConcat([{ b: 2 }])
result[0] === obj    // true — та же ссылка
obj.a = 99
result[0].a          // 99 — изменение видно в результате
```

Это ожидаемое поведение, а не баг: `concat` копирует ссылки, а не значения.

### 4. `Symbol.isConcatSpreadable`

Нативный `concat` перед раскрытием проверяет свойство `Symbol.isConcatSpreadable`:

```typescript
const arr = [1, 2]
arr[Symbol.isConcatSpreadable] = false
[0].concat(arr)      // [0, [1, 2]] — массив НЕ раскрылся

const fake = { length: 2, 0: 'a', 1: 'b', [Symbol.isConcatSpreadable]: true }
[0].concat(fake)     // [0, 'a', 'b'] — не-массив раскрылся
```

Данная реализация это намеренно не поддерживает: на собеседовании достаточно назвать этот нюанс вслух, реализация обычно не требуется.

## Пошаговое выполнение

Запуск: `[1, 2].myConcat(3, [4, 5], [[6]])`

| Шаг | Входной элемент | Как добавляется | Вклад в результат | `newArray` после шага |
|:---:|---|---|---|---|
| — | получатель `[1, 2]` | поверхностная копия | `1, 2` | `[1, 2]` |
| **0** | аргумент `3` | не массив → как одно значение | `3` | `[1, 2, 3]` |
| **1** | аргумент `[4, 5]` | массив → спред на один уровень | `4, 5` | `[1, 2, 3, 4, 5]` |
| **2** | аргумент `[[6]]` | массив → спред на один уровень | `[6]` | `[1, 2, 3, 4, 5, [6]]` |

*Результат:* `[1, 2, 3, 4, 5, [6]]`

---

## Граничные случаи

1. **Без аргументов**:
   - `[1, 2].myConcat()` — возвращает поверхностную копию `[1, 2]`, но это **новый** массив (`copy !== source`).
2. **Пустой получатель**:
   - `([] as number[]).myConcat(1, [2, 3])` — возвращает `[1, 2, 3]`.
3. **Пустой массив-аргумент**:
   - `[1].myConcat([], [2])` — возвращает `[1, 2]`, пустой аргумент не даёт вклада.
4. **Вложенный массив**:
   - `[1].myConcat([[2]])` — возвращает `[1, [2]]`, глубже одного уровня не раскрывается.
5. **`undefined` и `null` как аргументы**:
   - `[1].myConcat(undefined, null)` — возвращает `[1, undefined, null]`, они не массивы и добавляются как значения.
6. **Строка как аргумент**:
   - `[1].myConcat('ab')` — возвращает `[1, 'ab']`, а **не** `[1, 'a', 'b']`: строка итерируема, но не массив.
7. **Разреженный получатель**:
   - `([1, , 3] as number[]).myConcat(4)` — дыра в получателе сохраняется: `[1, <1 empty item>, 3, 4]`.
8. **Получатель не мутируется**:
   - После `original.myConcat(3)` сам `original` остаётся `[1, 2]`.

---

## Частые ошибки (Common Pitfalls)

1. **Рекурсивное раскрытие вместо одного уровня**:
   Рекурсивный «flatten»-хелпер превратит `[[6]]` в `6` и нарушит контракт метода. Раскрывать нужно только сам аргумент.
2. **Мутация получателя**:
   `this.push(...)` вместо работы с копией сломает главное свойство `concat` — чистоту. Всегда начинайте с `[...this]`.
3. **`instanceof Array` вместо `Array.isArray`**:
   Ломается на массивах из другого realm.
4. **Попытка итерировать любые итерируемые аргументы**:
   Строки, `Set`, `Map` итерируемы, но `concat` их **не** раскрывает — критерий только `Array.isArray`.
5. **Использование `push(item)` для массива-аргумента**:
   `newArray.push([4, 5])` добавит массив целиком одним элементом вместо раскрытия. Нужен спред: `push(...items[i])`.

## Особенности типизации в TypeScript

### 1. Почему одна сигнатура, а не несколько перегрузок

В отличие от `myReduce`, где тип аккумулятора зависит от наличия `initialValue` (отсюда три перегрузки), у `myConcat` тип результата выводится единообразно:

```typescript
myConcat<U>(...items: Array<U | Array<U>>): Array<T | U>
```

- `T` — тип элементов получателя, он всегда в результате.
- `U` — выводится из аргументов: `U | Array<U>` означает «либо одиночное значение, либо массив таких значений».
- Результат — `Array<T | U>`: объединение исходного типа и типа добавленных элементов.

Именно поэтому `[1, 2].myConcat('a')` выводится как `(number | string)[]` — расширять тип вручную не нужно.

### 2. Типизация разреженных и пустых массивов в тестах

- **Разреженные массивы**: `[1, , 3]` TypeScript выводит как `(number | undefined)[]`. Для тестов используйте явное приведение: `([1, , 3] as number[])`.
- **Пустые массивы**: `[]` типизируется как `never[]`, и `myConcat` на нём выведет `never` для `T`. Используйте `([] as number[])`.

## Точная версия по спецификации

Если требуется полное соответствие поведению нативного `concat` для дыр внутри аргументов-массивов, элементы копируются поэлементно с проверкой существования индекса:

```typescript
Array.prototype.myConcat = function <T>(this: T[], ...items: any[]): any[] {
  const result: any[] = []
  let index = 0

  const append = (value: any) => {
    if (Array.isArray(value)) {
      const length = value.length
      for (let i = 0; i < length; i++) {
        // Дыра остаётся дырой: индекс просто пропускается
        if (Object.hasOwn(value, i)) {
          result[index] = value[i]
        }
        index++
      }
    } else {
      result[index] = value
      index++
    }
  }

  append(this)
  for (let i = 0; i < items.length; i++) {
    append(items[i])
  }

  result.length = index
  return result
}
```

Здесь `result.length = index` нужен, чтобы завершающие дыры учитывались в длине: если последние индексы пропущены через `Object.hasOwn`, присваивания не было и `length` сам бы не вырос.

На собеседовании прямая реализация (со спредом) обычно предпочтительнее: она короче и покрывает всё, кроме дыр в аргументах. Спец-версию стоит держать в голове как ответ на уточняющий вопрос.

## Сложность алгоритма

- **Временная сложность**: $O(n + m)$, где $n$ — длина получателя, $m$ — суммарное количество добавляемых элементов. Каждый элемент копируется ровно один раз.
- **Пространственная сложность**: $O(n + m)$ — создаётся новый массив под все элементы результата. В отличие от `myReduce` ($O(1)$), здесь аллокация обязательна: метод возвращает массив, а не единичное значение.

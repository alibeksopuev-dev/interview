# Реализация `Array.prototype.myMap`

## Условие задачи

Реализовать метод `myMap` на прототипе `Array`, который ведёт себя идентично нативному `Array.prototype.map`:
- Применяет `callbackFn` к каждому **существующему** индексу массива.
- Поддерживает необязательный аргумент `thisArg` для привязки контекста внутри колбэка.
- **Сохраняет разреженность** (holes): пустые ячейки не превращаются в `undefined`.
- Возвращает **новый** массив той же длины.

---

## Реализация

```typescript
export {};

declare global {
  interface Array<T> {
    myMap<U>(
      callbackFn: (value: T, index: number, array: Array<T>) => U,
      thisArg?: any,
    ): Array<U>;
  }
}

Array.prototype.myMap = function <T, U>(
  this: T[],
  callbackFn: (value: T, index: number, array: T[]) => U,
  thisArg?: any,
): U[] {
  const len = this.length;
  const array = new Array<U>(len); // pre-size, сохраняет holes

  for (let k = 0; k < len; k++) {
    if (Object.hasOwn(this, k)) {
      array[k] = callbackFn.call(thisArg, this[k], k, this);
    }
  }

  return array;
};
```

## Ключевые детали

### 1. `new Array(len)` vs `[]`

`new Array(len)` создаёт массив с заданной длиной (`length === len`), но **без** собственных индексных свойств — все ячейки являются «дырами» (holes). Это важно: нативный `map` тоже не заполняет пропуски явными `undefined`.

```
[1, , 3].myMap(x => x * 2)
// → [2, empty, 6]  ← индекс 1 отсутствует как собственное свойство
```

Если использовать `[]` и `array.push(...)`, пропуски будут заполнены `undefined`, а не сохранены как holes.

### 2. `Object.hasOwn(this, k)` — проверка на hole

`in` проверяет цепочку прототипов. `Object.hasOwn` проверяет только **собственные** свойства объекта, поэтому корректно пропускает дыры разреженного массива.

```typescript
const sparse = [1, , 3];
Object.hasOwn(sparse, 0); // true
Object.hasOwn(sparse, 1); // false ← hole
Object.hasOwn(sparse, 2); // true
```

### 3. Дженерики `<T, U>` и их передача

В реализации `myMap` используются обобщенные типы (Generics) `<T, U>`:
- **`T`** — тип элементов исходного массива.
- **`U`** — тип элементов нового массива, получаемого в результате трансформации.

#### Как они передаются при вызове?
В большинстве случаев типы передаются **неявно** — TypeScript автоматически выводит (infer) их на основе контекста:
1. **Тип `T`** выводится из типа исходного массива, на котором вызывается `myMap`. Поскольку параметр `this` типизирован как `T[]`, TypeScript сопоставляет его с реальным массивом. Например, при вызове `[1, 2, 3].myMap(...)` тип `T` автоматически определяется как `number`.
2. **Тип `U`** выводится из возвращаемого значения функции `callbackFn`. Например, если колбэк возвращает строку `(val) => val.toString()`, то тип `U` автоматически определится как `string`, а результатом выполнения `myMap` будет массив строк `string[]`.

Если типы не могут быть выведены автоматически (например, при сложной цепочке вызовов или пустом массиве), можно указать дженерик явно при вызове. В сигнатуре `myMap<U>` объявлен только один параметр `U` на уровне метода, так как `T` уже зафиксирован на уровне интерфейса `Array<T>`:
```typescript
const numbers = [1, 2, 3]; // Array<number>, T = number
const strings = numbers.myMap<string>((val) => val.toString()); // U явно задан как string
```

### 4. В чем разница между `this` и `thisArg`?

В коде используются и `this` (в сигнатуре `this: T[]`), и `thisArg` (параметр `thisArg?: any`). Это абсолютно разные понятия:

*   **`this` (контекст вызова метода `myMap`)**
    *   Это ссылка на **исходный массив**, для которого вызывается метод `myMap`.
    *   В сигнатуре `this: T[]` — это так называемый *pseudo-parameter* в TypeScript, указывающий компилятору тип контекста `this` внутри функции. В итоговом JavaScript-файле этого параметра не будет.
    *   Внутри реализации `myMap` мы используем `this`, чтобы получить доступ к свойствам исходного массива: `this.length`, `this[k]`, а также для проверки на существование элементов с помощью `Object.hasOwn(this, k)`.
*   **`thisArg` (контекст для вызова колбэка)**
    *   Это необязательный аргумент, который пользователь передает вторым параметром при вызове метода: `arr.myMap(callback, thisArg)`.
    *   Он определяет, какой объект должен выступать в качестве `this` **внутри функции-колбэка** (`callbackFn`) при её вызове.

#### Зачем нужен `thisArg`, если уже есть `this`?
По умолчанию (в строгом режиме `'use strict'`) функция, переданная в качестве колбэка, вызывается с контекстом `this === undefined`. Если внутри колбэка разработчику нужно обратиться к свойствам или методам какого-то внешнего объекта через `this`, произойдет ошибка. Параметр `thisArg` позволяет прокинуть этот внешний объект.

*Важно помнить:* Стрелочные функции (`(x) => ...`) имеют лексический контекст `this` (берут его из внешнего окружения), поэтому для них `thisArg` не работает. `thisArg` учитывается только при вызове обычных функций (`function() {}`).

Пример использования:
```typescript
const calculator = {
  multiplier: 10,
  multiply(value: number) {
    // Без передачи thisArg, this.multiplier вызовет ошибку (TypeError: Cannot read properties of undefined)
    return value * this.multiplier;
  }
};

const numbers = [1, 2, 3];
// Передаем calculator вторым аргументом (thisArg)
const doubled = numbers.myMap(calculator.multiply, calculator); // [10, 20, 30]
```

### 5. Три параметра `callbackFn` и их назначение

Нативный `Array.prototype.map` вызывает функцию-колбэк, передавая в неё три параметра:
`callbackFn(currentValue, index, array)`

1.  **`currentValue` (`value` / `this[k]`)** — текущий обрабатываемый элемент массива.
    *   *Зачем нужен:* Самый важный параметр. Это значение элемента, на основе которого вычисляется результат трансформации.
2.  **`index` (`k`)** — индекс текущего обрабатываемого элемента.
    *   *Зачем нужен:* Полезен, когда логика преобразования зависит от позиции элемента. Например:
        *   Генерация уникальных ключей в UI (например, в React).
        *   Маппинг только четных/нечетных элементов.
        *   Специфические математические операции, завязанные на индекс.
3.  **`array` (`this`)** — ссылка на исходный массив, для которого был вызван метод `myMap`.
    *   *Зачем нужен:* Позволяет получить доступ к другим элементам исходного массива прямо из колбэка, не сохраняя его во внешнюю переменную. Например:
        *   Сравнение текущего элемента со следующими или предыдущими: `arr[index - 1]` или `arr[index + 1]`.
        *   Обращение к первому элементу массива `arr[0]` или получение общей длины `arr.length` в процессе обхода.

### 6. Зачем нужен `callbackFn.call` и как передаются аргументы

Для вызова колбэка с передачей `thisArg` используется стандартный метод `Function.prototype.call()`:
```typescript
array[k] = callbackFn.call(thisArg, this[k], k, this);
```

#### Что здесь происходит?
Метод `call` вызывает функцию, явно задавая её контекст `this` (первый аргумент `call`) и передавая последующие аргументы как параметры функции.

Разберем параметры вызова:
*   `callbackFn.call(...)` — вызов колбэка.
*   `thisArg` — первый параметр. Становится значением `this` внутри `callbackFn`. Если пользователь его не передал, придет `undefined` (что соответствует стандартному поведению `map` в строгом режиме).
*   `this[k]` — второй параметр. Становится первым аргументом `callbackFn` (`currentValue`).
*   `k` — третий параметр. Становится вторым аргументом `callbackFn` (`index`).
*   `this` — четвертый параметр. Становится третьим аргументом `callbackFn` (`array`). Напоминаем, что внутри `myMap` ключевое слово `this` указывает на сам исходный массив.

Схематично:
```typescript
array[k] = callbackFn.call(thisArg, this[k], k, this);
//                    ↑       ↑        ↑    ↑
//                    │       │        │    └─ 3й параметр: весь исходный массив (this)
//                    │       │        └────── 2й параметр: текущий индекс k
//                    │       └─────────────── 1й параметр: текущий элемент (this[k])
//                    └─────────────────────── this внутри колбэка (thisArg)
```

Примеры, демонстрирующие использование всех параметров:
```typescript
// 1. Использование currentValue (value)
[10, 20, 30].myMap((value) => value * 2);          // [20, 40, 60]

// 2. Использование index
[10, 20, 30].myMap((_, index) => index);           // [0, 1, 2]

// 3. Использование всего массива (array)
[10, 20, 30].myMap((v, i, arr) => v + arr[0]);    // [20, 30, 40] (arr[0] всегда равен 10)

// 4. Использование thisArg с обычной функцией
const ctx = { factor: 3 };
[1, 2, 3].myMap(function(v) { return v * this.factor; }, ctx); // [3, 6, 9]
```

### 7. Подробный разбор типизации (расширение `Array<T>`)

В начале файла `myMap.ts` мы декларируем сигнатуру метода с помощью расширения глобальных типов TypeScript:

```typescript
export {}; // Делает файл модулем, изолируя локальные объявления

declare global {
  interface Array<T> {
    myMap<U>(
      callbackFn: (value: T, index: number, array: Array<T>) => U,
      thisArg?: any,
    ): Array<U>;
  }
}
```

Разберем каждую строчку этой декларации:

1. **`export {};`**
   * В TypeScript файлы по умолчанию могут трактоваться как глобальные скрипты. Но под модульной системой (например, `NodeNext`) компилятор ожидает модульную изоляцию.
   * Строка `export {};` сообщает компилятору, что этот файл является **модулем** (module), а не просто скриптом (script). Это обязательное условие для использования конструкции `declare global`.

2. **`declare global`**
   * Это специальный синтаксический блок, который позволяет "внедриться" в глобальную область видимости (глобальный скоуп) из файла-модуля.
   * Без `declare global` интерфейс `interface Array<T>` стал бы локальным для файла `myMap.ts` и не повлиял на встроенный глобальный тип `Array`.

3. **`interface Array<T>`**
   * TypeScript поддерживает механизм **декларативного слияния** (Declaration Merging). Если объявить интерфейс с тем же именем, что уже существует в стандартной библиотеке (а `Array<T>` объявлен в `lib.es5.d.ts`), TypeScript объединит их свойства.
   * Наш новый метод `myMap` добавляется к существующим методам массивов (`map`, `filter`, `reduce` и др.).
   * **`T`** — это дженерик-параметр исходного массива. Он автоматически передается от инстанса массива. Если у нас есть `const arr: number[]`, то для него `T` будет равен `number`.

4. **`myMap<U>(...)`**
   * **`<U>`** — это собственный generic-параметр метода `myMap`. Он определяет тип элементов **нового массива**, который вернет метод.
   * `U` объявлен на уровне метода, потому что тип возвращаемого массива может отличаться от исходного (например, мы маппим числа `number` в строки `string`).

5. **`callbackFn: (value: T, index: number, array: Array<T>) => U`**
   * Это типизация функции обратного вызова (колбэка):
     * `value: T` — тип текущего элемента совпадает с типом элементов исходного массива `T`.
     * `index: number` — индекс текущего элемента (всегда число).
     * `array: Array<T>` — ссылка на исходный массив, тип которого также `Array<T>`.
     * `=> U` — колбэк должен вернуть значение типа `U`. Именно этот тип `U` станет типом элементов результирующего массива.

6. **`thisArg?: any`**
   * Опциональный параметр `thisArg` (на это указывает знак `?`).
   * Тип `any` означает, что контекстом может выступать абсолютно любое значение — объект, функция, примитив или `undefined`.

7. **Возвращаемое значение `: Array<U>`**
   * Метод возвращает **новый** массив, содержащий элементы типа `U` (то есть результат трансформаций колбэка).

## Пошаговое выполнение `[1, 2, 3].myMap(x => x * 2)`

| Шаг | `k` | `hasOwn` | `callbackFn(this[k], k, arr)` | `array[k]` |
|:---:|:---:|:--------:|:-----------------------------:|:----------:|
| 1 | 0 | `true` | `1 * 2` | `2` |
| 2 | 1 | `true` | `2 * 2` | `4` |
| 3 | 2 | `true` | `3 * 2` | `6` |

Результат: `[2, 4, 6]`

---

## Разреженный массив `[1, , 3].myMap(x => x * 2)`

| Шаг | `k` | `hasOwn` | Что происходит | `array[k]` |
|:---:|:---:|:--------:|:--------------|:----------:|
| 1 | 0 | `true` | Вызывает `1 * 2` | `2` |
| 2 | 1 | `false` | **Пропуск** (hole) | *(пусто)* |
| 3 | 2 | `true` | Вызывает `3 * 2` | `6` |

Результат: `[2, empty, 6]` — дыра сохранена.

## Частые вопросы

### Почему нельзя использовать `forEach` внутри?

`forEach` пропускает holes (хорошо), но не даёт контроля над результирующим массивом и не принимает `thisArg`. Кроме того, цель задачи — показать, что вы понимаете низкоуровневую механику `map`.

### Зачем `this.length` сохранять в `len`?

По спецификации `Array.prototype.map` читает длину **один раз** в начале. Если колбэк изменит длину массива в процессе — это не должно влиять на итерацию. Сохранение в `len` воспроизводит это поведение.

### Чем `Object.hasOwn` лучше `k in this`?

`in` ищет свойство по цепочке прототипов. Если на `Array.prototype` добавлено свойство с числовым ключом, `in` вернёт `true`, хотя это не элемент массива. `Object.hasOwn` проверяет только **собственные** свойства, что соответствует спецификации `map`.

### Зачем передавать `thisArg` первым аргументом в `callbackFn.call(thisArg, ...)`? (Простыми словами)

Представьте простую ситуацию. У нас есть объект пользователя и функция, которая здоровается, используя имя из этого объекта через `this.name`:

```javascript
const user = {
  name: "Иван",
  sayHi(item) {
    return `Привет, ${item}! Меня зовут ${this.name}`;
  }
};
```

Мы хотим применить эту функцию к элементам массива с помощью `myMap`:
```javascript
const items = ["яблоко", "банан"];
// Передаем саму функцию и объект user как контекст (thisArg)
const greeting = items.myMap(user.sayHi, user); 
```

**Что произойдет, если мы НЕ передадим `thisArg` в `.call()`?**

Если бы мы вызвали колбэк как обычную функцию `callbackFn(this[k], k, this)` без `.call(thisArg)`, то JavaScript при выполнении функции `sayHi` **потерял бы контекст `user`**. Внутри функции `sayHi` ключевое слово `this` стало бы равным `undefined` (в строгом режиме). Код попытался бы обратиться к `undefined.name`, и программа бы упала с ошибкой:
> `TypeError: Cannot read properties of undefined (reading 'name')`

**Зачем здесь `.call()` и первый аргумент `thisArg`?**

Метод `.call()` — это встроенный инструмент JavaScript. Он позволяет принудительно сказать функции: *«Когда будешь выполняться, считай, что `this` внутри тебя — это вот этот конкретный объект»*. 

И этот объект **всегда передается первым аргументом** в `.call()`:
```typescript
callbackFn.call(thisArg, currentItem, index, array);
```
Благодаря этому внутри функции `sayHi` значение `this.name` успешно превращается в `user.name` ("Иван"), и код отрабатывает без ошибок.

### Почему используется `call`, а не `apply`?

Методы `call` и `apply` делают одно и то же — вызывают функцию с заданным контекстом `this`. Различие состоит в способе передачи остальных аргументов:
- `call` принимает аргументы **перечислением** через запятую: `func.call(thisArg, arg1, arg2, ...)`.
- `apply` принимает аргументы **единым массивом**: `func.apply(thisArg, [arg1, arg2, ...])`.

Технически мы могли бы написать:
```typescript
array[k] = callbackFn.apply(thisArg, [this[k], k, this]);
```
Этот код будет работать абсолютно так же, но использование `call` является лучшей практикой по двум причинам:

1.  **Производительность и память (Garbage Collection):**
    При вызове `apply` нам приходится на каждой итерации цикла создавать новый временный массив `[this[k], k, this]`. Если в массиве $N$ элементов, интерпретатор JavaScript создаст и уничтожит $N$ массивов в куче (heap). Это создает лишнюю работу для сборщика мусора и снижает скорость работы. Метод `call` передает аргументы через стек вызовов напрямую без выделения памяти под массивы.
2.  **Читаемость и семантика:**
    Когда количество аргументов фиксировано и известно заранее (в нашем случае их ровно три), использование `call` выглядит чище и лаконичнее. `apply` обычно применяется, когда количество аргументов динамическое или они изначально хранятся в виде массива.

## Сложность алгоритма

- **Временная сложность**: $O(n)$ — один проход по всем индексам.
- **Пространственная сложность**: $O(n)$ — результирующий массив той же длины.

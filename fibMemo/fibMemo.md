# Фибоначчи с мемоизацией (`fibMemo`)

## Условие задачи
Реализовать функцию вычисления $n$-го числа Фибоначчи с использованием мемоизации (кэширования) для оптимизации временной сложности от экспоненциальной $O(2^n)$ до линейной $O(n)$.

---

## Важная деталь (Частая ошибка)
В исходном коде:
```javascript
function fibMemo(n, memo = {}) {
  if (n <= 1) return n;
  if (memo[n]) return memo[n];
  memo[n] = fibMemo(n-1) + fibMemo(n-2); // <-- Ошибка: memo не передаётся дальше!
  return memo[n];
}
```
**Проблема**: Без передачи аргумента `memo` в рекурсивные вызовы `fibMemo(n-1)` и `fibMemo(n-2)`, при каждом вызове функции создаётся новый пустой объект `memo = {}` по умолчанию. Кэш сбрасывается и мемоизация не работает между ветвями рекурсии.

**Исправление**:
```typescript
memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
```

## Частые вопросы

### Что такое "левая" и "правая" ветвь?

В выражении `fibMemo(n-1, memo) + fibMemo(n-2, memo)` JavaScript вычисляет операнды слева направо:

```
fibMemo(5)
├── fibMemo(4)   ← левая ветвь (n-1), выполняется первой
└── fibMemo(3)   ← правая ветвь (n-2), выполняется после
```

JS сначала уходит вглубь по левой ветви до базового случая, возвращается с результатом, и только потом вызывает правую ветвь. К этому моменту кэш уже заполнен, поэтому правая ветвь часто берёт результат из `memo` без лишней рекурсии.

---

### Зачем базовый случай покрывает `F(0) = 0`?

Числа Фибоначчи по определению:

```
F(0) = 0
F(1) = 1
F(2) = 1
F(3) = 2
...
```

Без остановки на `0` рекурсия ушла бы в бесконечность: `F(2)` → `F(1)` + `F(0)` → `F(0)` + `F(-1)` → ...

Проверка `n <= 1` покрывает оба базовых случая одной строкой:
- `n === 0` → возвращает `0`
- `n === 1` → возвращает `1`

## Сложность алгоритма

- **Временная сложность**: $O(n)$
  Благодаря кэшированию каждое число Фибоначчи от $2$ до $n$ вычисляется рекурсивно ровно один раз. Все последующие обращения к этим числам происходят за константное время $O(1)$ из объекта кэша.
- **Пространственная сложность**: $O(n)$
  - Объект `memo` хранит до $n$ записей.
  - Стек вызовов в пиковой точке (при спуске по левой ветке) достигает глубины $n$ кадров.

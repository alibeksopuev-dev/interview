# Debounce и Throttle — подробное объяснение с примерами

> Перевод статьи: https://css-tricks.com/debouncing-throttling-explained-examples/

---

## Зачем это нужно

DOM-события могут срабатывать непредсказуемо часто. Событие `scroll`, например, вызывается до **30 раз в секунду** на десктопе и до **100 раз** на мобильных устройствах. Если к таким событиям привязана тяжёлая операция (запрос к API, пересчёт DOM), это ведёт к деградации производительности.

**Debounce** и **throttle** — два дополняющих друг друга приёма, которые позволяют контролировать частоту вызовов функции в ответ на события.

---

## Debounce

### Суть

Debounce **группирует серию быстрых последовательных вызовов в один**. Функция выполняется только когда события прекращаются на заданный интервал времени.

### Аналогия с лифтом

Двери лифта закрываются — заходит ещё один человек — двери снова открываются. Лифт не едет до тех пор, пока активность не прекратится. Именно так работает debounce: он откладывает выполнение до паузы.

### Два варианта: trailing и leading

**Trailing (по умолчанию)** — выполнение происходит *после* того, как события прекратились.

```
events:  ----e--e--e---------e-----
         [  debounce 300ms  ]
result:  ------------------X------X
```

Применение: автодополнение в поиске — хочется подождать, пока пользователь закончит печатать.

---

**Leading (немедленный)** — выполнение происходит *сразу* при первом событии, а последующие вызовы игнорируются до паузы.

```
events:  ----e--e--e---------e-----
         [  debounce 300ms leading ]
result:  ----X---------------X-----
```

Применение: мгновенная реакция на первое действие без повторных срабатываний.

### Параметр maxWait

Lodash предоставляет дополнительный параметр `maxWait` — максимальное время ожидания, после которого функция всё равно будет вызвана, даже если события не прекращались.

### Частая ошибка

```js
// ❌ Неправильно — новая debounced-функция создаётся на каждое событие
element.addEventListener('keyup', function() {
  _.debounce(doSearch, 300)(); // бесполезно
});

// ✅ Правильно — debounced-функция создаётся один раз
const doSearchDebounced = _.debounce(doSearch, 300);
element.addEventListener('keyup', doSearchDebounced);
```

## Throttle

### Суть

Throttle **гарантирует выполнение функции не чаще одного раза за заданный интервал**. В отличие от debounce, он не ждёт паузы — он поддерживает равномерный ритм вызовов.

```
events:  ----e--e--e--e--e--e-----
         [   throttle 300ms      ]
result:  ----X--------X--------X--
```

### Применение: infinite scroll

Идеальный кейс — бесконечная прокрутка. Нужно периодически проверять позицию скролла и подгружать контент *до того*, как пользователь доберётся до низа страницы, а не после того как он уже достиг конца. Debounce здесь не подойдёт — он бы выполнился только после остановки скролла.

## requestAnimationFrame (rAF)

### Суть

`requestAnimationFrame` — браузерный API, который выполняет функцию перед следующей перерисовкой. Нацелен на 60 кадров/сек (~16 мс). По точности превосходит `throttle`.

### Преимущества

- Нативная оптимизация браузером для анимаций
- Стандартизированный API, минимум поддержки

### Ограничения

- Требует ручного управления (start/cancel)
- Не выполняется в неактивных вкладках
- Не работает в Node.js
- Нужен полифил для IE9 и старых окружений

### Когда использовать

Используй rAF для **анимаций и перепозиционирования элементов**. Для запросов к API и условной логики лучше подходят debounce/throttle с интервалом ~200 мс (против 16 мс у rAF).

## Сравнительная таблица

| Техника | Принцип | Лучшие сценарии |
|---------|---------|-----------------|
| **Debounce** | Группирует всплески в одно выполнение | Поиск, валидация форм, resize |
| **Throttle** | Равномерные выполнения через интервал | Infinite scroll, проверка позиции |
| **rAF** | Синхронизация с перерисовкой браузера | Анимации, пересчёт DOM |

---

## Вывод

- Используй **debounce**, когда важна только *финальная* реакция после серии событий.
- Используй **throttle**, когда нужна *регулярная* реакция во время непрерывного потока событий.
- Используй **rAF**, когда обновляешь визуальные элементы и нужна синхронизация с отрисовкой.
- Не пиши реализации с нуля — используй **Lodash** (`_.debounce`, `_.throttle`).
